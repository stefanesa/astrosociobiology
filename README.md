# Astro-Sociobiology

Source for [astrosociobiology.com](https://astrosociobiology.com): a lightweight, academic-journal-style blog about the speculative science of what advanced alien societies might be like.

**At a glance**

| Thing | How it works |
|---|---|
| Content | Markdown files in `content/posts/` |
| Site generator | `build.js`, a single ~200-line Node script (deps: `marked`, `gray-matter`) |
| Hosting | GitHub Pages, deployed by GitHub Actions on every push to `main` |
| CMS | `/admin/`, a static browser editor that commits to this repo via the GitHub API |
| Database / server | None |
| Cost | Free (domain registration aside) |

---

## 1. How it was built

### Architecture

```
 you ──write──▶ /admin/ (browser) ──GitHub API commit──▶ repo (main)
                                                           │ push triggers
                                                           ▼
                                           GitHub Actions: npm ci && node build.js
                                                           │ uploads dist/
                                                           ▼
                                      GitHub Pages ──▶ astrosociobiology.com
```

Everything is plain files in git. The git history is the backup, the audit log and the "undo" button.

### Repository layout

```
content/
  posts/            articles (Markdown + YAML front matter)
  pages/            static pages (about.md -> /about/)
  images/           uploaded images, published at /images/
static/
  style.css         site stylesheet (light/dark, print-friendly)
  favicon.svg
  admin/            the CMS: index.html, admin.js, admin.css
site.config.json    title, tagline, author, domain, GitHub repo, founding year
build.js            the generator
.github/workflows/deploy.yml   build + deploy to Pages
dist/               build output (git-ignored, regenerated by CI)
```

### What `build.js` does

1. Reads `content/posts/*.md`, skipping any with `draft: true`, and sorts by date.
2. Computes the journal metadata, so nothing is numbered by hand:
   - **Volume** = `year - foundingYear + 1` (2025 is Vol. I, 2026 is Vol. II, ...)
   - **Article number** = order of publication within the volume
   - A **citation** string for each article.
3. Renders HTML for: home (latest 5), each article, the archive (grouped by volume), a page per keyword, static pages, and a 404.
4. Emits `feed.xml` (RSS), `sitemap.xml`, `robots.txt`, and a `CNAME` file derived from `site.config.json`.
5. Copies `static/` and `content/images/` into `dist/`, plus `admin/config.json` (the repo coordinates the editor needs).

### How the CMS works

`static/admin/` is a single-page app with no backend. It uses the GitHub REST "contents" API directly from your browser:

- **Sign-in:** you paste a fine-grained personal access token. It is kept in that browser's `localStorage` and sent only to `api.github.com`.
- **List / open:** reads `content/posts/` and parses each file's front matter.
- **Save:** `PUT`s the Markdown file as a commit on `main` (message "Add article: ..." or "Update article: ..."). Editing uses the file's SHA, so if the file changed elsewhere in the meantime you'll get a conflict message instead of silently overwriting.
- **Delete:** a commit that removes the file (still recoverable from history).
- **Images:** committed to `content/images/` and inserted into the article as `![alt](/images/name)`.
- **Preview:** renders Markdown in the browser with `marked` (loaded from jsDelivr, pinned to 12.0.2, the same version the build uses).

Because every save is a push to `main`, the Actions workflow rebuilds and redeploys the site automatically, usually in 30 to 90 seconds.

## 2. Posting new content

### Option A: the web editor (recommended)

1. Go to **https://astrosociobiology.com/admin/** and sign in (see [Admin](#3-admin-and-operations) for the token).
2. Click **+ New article**. Fill in:
   - **Title**: the slug (URL) is generated from it; edit it before the first save if you like. A slug can't be changed after saving.
   - **Type**: Essay, Primer, Field Note, Response or Review.
   - **Date**: controls ordering and which volume it lands in.
   - **Abstract**: 1 to 3 sentences, shown in listings and atop the article.
   - **Keywords**: comma-separated. Each becomes a browsable keyword page.
   - **Author**: leave blank to use the site default.
3. Write the body in Markdown. Use **Preview** to check it. **Insert image** uploads a picture (max 5 MB) and drops the Markdown into the text.
4. Tick **Draft** to keep it off the site, or untick it to publish.
5. Press **Save & publish** (or ⌘/Ctrl-S). The article is live after the build finishes; the list page has a link to build status.

To edit an existing article, click its title in the list. To unpublish without deleting, open it, tick *Draft*, and save.

### Option B: edit files directly

Add `content/posts/my-slug.md` (via git, or the GitHub web UI), commit to `main`:

```markdown
---
title: "My Title"
date: 2025-05-01
type: Essay            # Essay | Primer | Field Note | Response | Review
author: "Someone Else" # optional; defaults to site.config.json
abstract: "One to three sentences."
keywords: [evolution, economics]
draft: false           # true hides it from the site
---

Markdown body...

## A section heading

*italic*, **bold**, [a link](https://example.com), and:

> a block quote

- a list
```

Notes:
- Quote the `title` and `abstract` if they contain a colon.
- The filename (minus `.md`) is the URL: `my-slug.md` becomes `/posts/my-slug/`.
- Use `##` for section headings inside an article; the page title is already the `h1`.
- Images: put files in `content/images/` and reference them as `![alt text](/images/file.png)`.

### Changing static pages

Edit `content/pages/about.md` (it only needs a `title:` in the front matter). Any new `content/pages/foo.md` is published at `/foo/`; add a link to it in the nav inside `build.js` if you want it in the menu.

## 3. Admin and operations

### One-time setup (already done)

- GitHub repo `stefanesa/astrosociobiology` (public; required for free Pages).
- Pages enabled with **Source: GitHub Actions** (Settings, Pages).
- Custom domain `astrosociobiology.com` set in Pages settings.

### DNS (at the domain registrar)

Point the apex domain at GitHub Pages with four `A` records:

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

Optionally add a `CNAME` record for `www` pointing to `stefanesa.github.io`. Then in the repo's **Settings, Pages**, wait for the DNS check to pass and enable **Enforce HTTPS**. DNS changes can take from minutes to a day. Until then the site is reachable at `https://stefanesa.github.io/astrosociobiology/` (styling and links may look broken there because the site uses root-relative paths and expects to live at the custom domain).

### The editor token

The editor needs a **fine-grained personal access token**:

1. https://github.com/settings/personal-access-tokens/new
2. *Repository access* → **Only select repositories** → `astrosociobiology`
3. *Permissions → Repository → Contents* → **Read and write** (nothing else is needed)
4. Choose an expiry (e.g. 90 days to 1 year), generate, and paste it into `/admin/`.

Security notes:
- The token can publish to the site. Treat it like a password and don't paste it into the page on a shared computer. **Sign out** (top right) removes it from the browser.
- It is scoped to this one repo, so the blast radius is small. Revoke or regenerate it any time at https://github.com/settings/personal-access-tokens.
- When it expires, the editor shows "Token rejected or expired"; just create a new one.
- `/admin/` is publicly reachable but useless without a token; it's marked `noindex` so search engines skip it. The site does not use GitHub OAuth, so there is no client secret to protect.
- To allow another author, add them as a collaborator on the repo; they create their own token. Their commits are attributed to them.

### Day-to-day checks

- **Build status:** https://github.com/stefanesa/astrosociobiology/actions . A red ✗ means a build failed (usually malformed front matter); the log shows the file. Fix the file and push again; the last good version stays live meanwhile.
- **Re-run a deploy:** Actions → *Build & deploy* → *Run workflow* (or `gh workflow run deploy.yml`).
- **Undo a bad edit:** use the repo's commit history, then `git revert <commit>` (or revert in the GitHub UI).
- **Backup:** `git clone` the repo; that's the entire site and all its history.

### Local development

```sh
npm install
npm run serve        # builds, then serves http://localhost:8080
node build.js        # just build into dist/
```

Requires Node 18+ (CI uses Node 22). Note that `/admin/` talks to the live GitHub repo even when served locally.

### Site-wide settings (`site.config.json`)

| Key | Meaning |
|---|---|
| `title`, `tagline` | Masthead and page titles |
| `url` | Canonical URL, feed links, and the generated `CNAME` |
| `author` | Default byline and copyright line |
| `foundingYear` | Year that counts as Volume I |
| `github` | `owner` / `repo` / `branch` the editor commits to |

If you rename the repo or move it to another account, update `github` here and the DNS `www` target.

### Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Editor: "Could not connect: 404" | Token isn't scoped to this repo, or the repo name in `site.config.json` is wrong |
| Editor: "403" or "cannot write" | Token lacks *Contents: Read and write* |
| Editor: conflict on save | The file changed elsewhere; reload the article, re-apply your edit |
| Saved but not on the site | Build still running, or failed (check Actions); also check *Draft* isn't ticked |
| Preview shows nothing | jsDelivr blocked or offline; saving still works |
| Image missing after upload | Images appear after the next build finishes |
| HTTPS warning on the domain | DNS not propagated yet, or *Enforce HTTPS* not yet available; retry later |
| Article lands in the wrong volume/number | Check its `date`; volume comes from the year, number from date order |
